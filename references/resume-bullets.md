# Writing Resume Bullets

A good bullet shows what changed because the user was there. This file covers the impact formula, verbs, rewriting for a posting, and how to get real numbers from the user without inventing them.

## 1. The impact formula

Use this shape: **Accomplished [X], measured by [Y], by doing [Z].**

- **X** is the outcome: what improved, shipped, grew, or got fixed.
- **Y** is the evidence: a number, a scale, a comparison, or a named result.
- **Z** is the method: the skills and tools used, which is where the posting's keywords go.

The order can change. Leading with the result is usually strongest, but "Built Z, which achieved X (Y)" also works. What matters is that all three parts are present.

When there is truly no number, use scope or a concrete outcome instead:

- Scope: "for 4 regional offices", "across a 30-person engineering org", "for a product with 2M monthly users".
- Outcome: "adopted as the team standard", "cited by the CFO in the annual review", "removed the need for a weekend on-call rotation".

## 2. Bullet rules

- Start with a strong past-tense verb (present tense for the current role is fine, but be consistent within a role).
- One idea per bullet. One or two lines long.
- 3-6 bullets for recent or relevant roles, 1-3 for older or unrelated roles.
- Put the bullet most relevant to the posting first in each role.
- No personal pronouns ("I", "my").
- Avoid "responsible for", "helped with", "worked on", "assisted in". They describe duties, not results. If the user truly assisted, say what part they did: "Built the test suite for..." rather than "Helped with testing".
- Spell out what is unclear to an outsider; drop internal project code names.
- Numbers as digits: "5 analysts", "40%", "$1.2M".

## 3. Action verbs by type of work

Pick verbs that are accurate. "Led" means the user actually led.

| Type of work | Verbs |
| --- | --- |
| Building | Built, Designed, Developed, Engineered, Launched, Shipped, Prototyped |
| Improving | Reduced, Increased, Cut, Accelerated, Streamlined, Automated, Redesigned |
| Leading | Led, Directed, Managed, Mentored, Coached, Hired, Coordinated |
| Analysis | Analyzed, Modeled, Forecast, Diagnosed, Audited, Measured, Identified |
| Revenue and growth | Grew, Won, Closed, Negotiated, Expanded, Converted, Retained |
| Communication | Presented, Wrote, Trained, Published, Facilitated, Persuaded |
| Operations | Organized, Scheduled, Delivered, Standardized, Resolved, Maintained |
| Research | Investigated, Tested, Validated, Surveyed, Interviewed, Discovered |

## 4. Before and after examples

These examples are illustrative. Their numbers are part of the example only. For the user, use their own facts or placeholders.

**Customer support**

- Before: Responsible for answering customer tickets.
- After: Resolved about 45 support tickets per day with a 96% satisfaction score by writing reusable macros for the 10 most common issues.

**Software engineering**

- Before: Worked on the checkout page.
- After: Cut checkout page load time from 4.1s to 1.6s by moving image processing to a CDN and lazy-loading payment scripts, lifting mobile conversion by 7%.

**Marketing**

- Before: Managed social media accounts.
- After: Grew LinkedIn followers from 3,000 to 11,000 in 9 months by launching a weekly customer-story series with the sales team.

**Operations**

- Before: Helped improve the onboarding process.
- After: Redesigned the new-hire onboarding checklist used by 6 departments, reducing time to first full week of productive work from [X] to [Y] days.

The last example keeps placeholders because the numbers are not yet known. That is the correct behavior.

## 5. Finding numbers honestly

Never estimate a number for the user. Ask instead. Useful questions:

- How many people, customers, users, tickets, accounts or products did this affect?
- How often did you do it (per day, week, month)?
- What was it like before, and after? Even a rough "about half the time" from the user is fine if they confirm it.
- How much money, time or effort did it save or bring in?
- How big was the team, budget or scope?
- Did anyone outside your team adopt it, praise it or build on it?
- Where did it rank (top 10%, first in region, fastest delivery that year)?

Rules:

- If the user gives an estimate, mark it with "about" or "roughly" unless they confirm it is exact.
- If the user cannot share a number (confidential), use relative terms the user approves: "doubled", "cut by more than half", or scope instead.
- If the user does not know, keep the bullet without a number. A clear, true bullet beats a vague invented one.

Ask the questions in one grouped list at the end of the resume output, tied to the bullet each number belongs to:

```
Numbers I need from you:
1. Acme, bullet 2: roughly how many invoices per month did the new process handle? [X]
2. Acme, bullet 4: how long did reconciliation take before and after? [before] -> [after]
```

## 6. Rewriting for a posting

1. Take the requirement list from the fit analysis.
2. For each must-have with Strong or Partial evidence, find the bullet that proves it.
3. Rewrite that bullet so the posting's term appears naturally, if it is accurate. Example: the posting says "stakeholder management" and the user wrote "worked with sales and finance". Rewrite: "Aligned sales and finance stakeholders on a shared forecast model...".
4. Move that bullet to the top of its role.
5. Do not change the meaning. If the posting term overstates what the user did ("owned the roadmap" when they contributed to it), use the accurate phrase.

## 7. Common mistakes

- Listing duties copied from the old job description instead of results.
- Every bullet starting with the same verb.
- Bullets longer than two lines.
- Stacking several tools in one bullet with no outcome ("Used Python, SQL, Tableau, Excel, Jira").
- Claiming team results as personal results. Use "Co-led" or "As part of a 5-person team" when that is the truth.
- Vague adjectives ("significantly", "successfully", "various") instead of facts.
